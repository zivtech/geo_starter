## Proposal-critic review + resolutions (2026-06-09)

**Verdict: APPROVE-WITH-CHANGES (subset) + REVISE (the "+ optional MCP" half).**
Strategy survives the murder board (defer blocked MCP track, ship dependency-free
subset, opt-in add-on). Dropping `mcp_server` + `simple_oauth` restores the released
1.0.0 stable floor — verified `composer.json` byte-identical to released `main`. But
the carve surface is **14 files, not the 7 the plan named**, and two gates give false
green. Fold these in before an executor starts:

**B1 (BLOCKER) — schema drift-guard is blind to the MCP prose it ships.**
`tools/generate-content-model-schema.php --check` compares only `contentTypes` +
`workflow.states` and PRESERVES hand-authored prose on regen. `content-model.schema.json`
carries MCP refs in that prose (`moduleProviders.mcp`, `workflow.agentWriteRule`,
`$defs` `$comment` "…MCP validate_node tool", description). So DoD #4 passes GREEN while
the public machine-readable schema still advertises uninstalled MCP tools.
→ RESOLUTION: add a DoD gate = **mechanical MCP-residue grep over the shipped (non
export-ignored) artifact**, explicitly incl. `content-model.schema.json` + `openapi.yaml`,
asserting zero `mcp|simple_oauth|oauth|geo_agent|geo\.(describe|list_nodes|get_node|validate_node|create_node)`
except `OPTIONAL_MCP.md`. Sequence: **strip prose → THEN regenerate** (never reverse).

**M1 — narrative re-architecture, not line deletion.** MCP is the documented WRITE step
of the agent loop (install→inspect→**modify**→verify) across `AGENT_GUIDE.md` §3,
`README.md`, `AGENTS.md`, `INSTALL.md`. → re-architect "Modify" consistently (route to
editorial UI, or "opt-in — see OPTIONAL_MCP.md"); don't excise lines leaving a 4-step
loop with no write step.

**M2 (the REVISE) — `OPTIONAL_MCP.md` as scoped describes a NON-WORKING path.**
`geo_starter_mcp/composer.json` requires `drupal/mcp_server:^1.0` and `.info.yml` lists
`mcp_server:mcp_server` — and `^1.0` does NOT satisfy `2.x-dev` (the only installable
mcp_server). **So the prior claim "geo_starter_mcp can be built/tested vs 2.x-dev" is
FALSE as the package stands** (corrects this plan + the readiness-plan Correction note).
→ RESOLUTION: scope `OPTIONAL_MCP.md` to ONLY the transport + OAuth foundation that
actually works on `2.x-dev` today; state the typed GEO tools ship later (when mcp_server
tags). If the companion must install now, add an explicit step to relax ITS constraint to
`^1.0 || ^2.0` and test. Prescribe a **scoped per-package `drupal/mcp_server:2.x-dev`
constraint with `@dev` + `prefer-stable: true`** — NOT global `minimum-stability: dev`
(cascades dev across the whole consumer project).

**M3 — composer `suggest` block dangles.** `composer.json` `suggest.drupal/geo_starter_mcp`
points at removed `docs/MCP.md` + the unpublished package; `composer validate --strict`
won't catch it. → drop/rewrite it (add to the DROP enumeration).

**M4 — DoD #1 ≠ DoD #3.** `ddev geo-install` wires a `@dev` Composer PATH repo →
bypasses `minimum-stability`, so it can't prove the stable-floor property. → DoD #1 must
use the **released-artifact method** (git-archive tag tree, real d.o module, default
stability) as a distinct gate; #3 cannot substitute.

**M5 — reconcile ROW-BY-ROW vs released `main` (`35041a9`), not vaguely.** PR branched
from `3016600` (ancestor of released main). The GEO Readiness "Agent / tool protocol"
row was flipped Planned→Yes — must REVERT to Planned/opt-in. The PR's `## 1.1.0` CHANGELOG
block describes MCP as shipped — **rewrite from scratch**, do not port.
